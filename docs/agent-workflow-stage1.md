# Этап 1 — организация работы в GitHub

## Состояние

- `main` — публикуемая версия; работа над задачами идёт в `feature/*`, `fix/*`, `audit/*` и `chore/*`.
- Каждое изменение: Issue → рабочая ветка → PR → CI → предварительный просмотр → одобрение владельца → merge → Pages.
- PR содержит критерии приёмки, описание изменений, результаты тестов, ссылку на превью и последствия для сохранённых данных.
- При неизвестных игровых формулах писать `RULES-REVIEW REQUIRED`; не придумывать механику.
- Защита `main` на уровне GitHub Rulesets/Branch protection должна быть включена владельцем репозитория в Settings: этот этап не располагает доступом к API настроек защиты.

## Рекомендуемая защита main (владелец включает в Settings → Rules → Rulesets)

1. Создать branch ruleset с целью `main` и включить enforcement `Active`.
2. Require a pull request before merging; minimum 1 approval от другого уполномоченного участника, если он есть. При единственном владельце этот пункт не заменяет его явного одобрения в обсуждении PR.
3. Require status checks to pass: `check` из workflow `CI` (после того как GitHub предложит этот check).
4. Require conversation resolution before merging; запретить force pushes и удаление `main`.
5. Не включать автоматический merge. Проверить, что правила действительно применяются к `main` на текущем тарифе/типе репозитория.

## Предпросмотр

Текущий `.github/workflows/deploy.yml` публикует фиксированную ветку `audit/template-v2-pipeline` по адресу `/character-sheet/preview/` при сборке `main`. Это **не универсальное превью для каждого PR**: новые PR туда автоматически не попадают. Перед публикацией требуется проверить успешный workflow Deploy GitHub Pages и доступность URL. Создание изолированного превью для каждого PR — отдельная задача этапа 5. Не выдавать фиксированный адрес за актуальное превью произвольного PR.

## Контрольные точки

- Issue оформлен по шаблону.
- PR создан из рабочей ветки; `main` не редактируется напрямую.
- CI зелёный; проверены сборка и тесты.
- Есть фактически доступное превью или честно зафиксировано его отсутствие.
- Владелец одобрил результат после просмотра; только тогда merge.

## Что пока не сделано

- Серверная защита `main` (требует изменения настроек GitHub).
- Автоматический запуск автономных агентов (этап 2).
- Универсальные per-PR previews (этап 5).
